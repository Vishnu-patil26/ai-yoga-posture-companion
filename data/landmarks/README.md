# Landmark and angle dataset

Pose landmarks and joint angles for every photograph of the ten asanas used in this project, in a
layout modelled on the *Yoga-Poses-Dataset* by Manoj-2702 (one landmark CSV, one angle CSV and one
combined CSV per pose, plus a folder of skeleton images per pose) but with a documented schema,
nothing dropped silently, and a checker. Generated by `tools/datasets/export_landmarks.py` with the
same BlazePose tracker the app uses; verified by `tools/datasets/validate_landmarks.py` and
`tests/test_landmark_export.py`.

## Layout

```
data/landmarks/
  manifest.csv        one row per source photo, detected or not - nothing is dropped silently
  columns.csv         data dictionary: every column, its unit and meaning
  all_poses.csv       every detected photo, all poses, one table (same columns as combined.csv)
  <pose>/             tadasana trikonasana virabhadrasana utkatasana vrikshasana
    landmarks.csv       image_id + 33 landmarks x (x, y, z, vis) = 133 columns
    angles.csv          image_id + 34 named joint angles and body measurements
    combined.csv        image metadata + angles + landmarks, ready for machine learning
    skeletons/          <image_id>.png - the detected skeleton on black (never over the photo)
                      adho_mukha bhujangasana marjaryasana balasana sukhasana (same files)
```

## The columns that matter

* `image_id` - stable id `<pose>_<source>_<nnnn>`; joins every file in this folder.
* `pose` is the class label. `variant` is an accepted form (`cat`, `cow`, `arms up`, `arms down`, `Warrior II`)
  or a dataset step. `quality` is `right` / `wrong` where the source labels form (Yoga for all), else
  `unlabelled`; `fault` names the wrong part (`Legs`, `Hand and Neck`...).
* `split` - `train`; `test` (TensorFlow set's own test split); `holdout` (set aside by `build_library.py`,
  never fitted on); `external` (labelled right/wrong photos, never fitted on).
* `<LANDMARK>_x`, `_y` - image-normalised position (0-1, y grows downward); `_vis` - BlazePose visibility.
  **`_z` is world depth in metres, hip-centred**, not the image-relative z of raw BlazePose output.
* Angles are interior angles in degrees (180 = straight). `left_/right_` columns depend on which side the
  person is on; `knee_bent`, `hip_angle_min`... are mirror-invariant (the more bent of the two sides);
  `*_vis` read the side the camera can see. Full definitions in `columns.csv`.
* `usable` - torso visible enough to score, the same gate the pose fits use.

| `ZEN` *Yoga for all*, Zenodo 7818789 | CC BY 4.0 | yes, a sample (`data/datasets/yoga_for_all`) |

| `Y107` Hugging Face `rotemvahava/yoga-poses-107` | not stated by the host (web photographs); included for research and education, removal on request | yes (`data/datasets/yoga107`) |

Landmarks and angles are numbers derived from the photographs and the skeleton images are drawn on
black, so no photograph is reproduced here; the `image` and `image_in_repo` columns say where each source photo
is and whether it is committed.

## Known limits

* One person (or two) per pose in `ZEN`; the diversity gap is the reason for `collect.py`.
* TF `warrior` mixes Warrior I, II and III (`variant = mixed Warrior I/II/III`); strict Warrior II comes from `Y107`.
* Landmarks come from a single 2-D camera view; depth `z` is the model's estimate, not a measurement.
* Photos differ in resolution and crop, so absolute pixel positions are not comparable - use the normalised
  columns and the angles.
